# Nielsen の第8ヒューリスティックと視覚的クラッター研究

調査日: 2026-10-24

対象: Nielsen (1994) のユーザビリティ・ヒューリスティック、とくに第8項、および Rosenholtz, Li, Nakano (2007) の視覚的クラッター指標

## 要点

Nielsen の第8ヒューリスティックは、必要な情報を削る規則でも、見た目を無装飾にする規則でもない。画面上の各情報・視覚要素を、利用者の主な目的に照らして検討し、無関係またはめったに使われない情報が重要な情報との競合を生まないようにするための点検観点である。現行ページは「フラットデザインを要求しない」と明記する。ページには1994年の日付と2024年の最終レビュー日が併記されており、現在の説明文を1994年当時の逐語的な原文として扱うべきではない。

Rosenholtz らは視覚探索の成績を予測する画像統計量として Feature Congestion、Subband Entropy、Edge Density を比較した。主な実験は地図上での短時間の探索であり、あらゆる画面の理解しやすさ、美しさ、業務成果を測ったものではない。実験1・2の指標と成績の関係は地図画像間の相関で、スコアを下げるとユーザビリティが改善するという因果証明ではない。第3実験では地図の色変動を操作し、特定条件の視覚探索への影響を示した。一般的な「色を減らすべき」という規則までは導かれない。

## 1. Nielsen の第8項をどう読むか

Nielsen Norman Group の現行ページは第8項を「Aesthetic and Minimalist Design」とし、無関係またはめったに必要とされない情報を表示しないよう勧める。余分な情報単位は関連情報と競合し、相対的な視認性を下げるという説明である。同ページは、視覚要素が利用者の主な目標を支援することを求め、デザインの平坦さを条件にしていない。したがって「ミニマル」は画面内の情報量や装飾量を機械的に最小化する意味ではなく、目的に対して何が関連するかを問う基準と読むのが適切である。

歴史上の年と現在のページを区別する。ページの冒頭には「1994年4月24日」と「2024年1月30日最終レビュー」が表示される。著者注によると、ヒューリスティックは Rolf Molich と1990年に開発を始め、1994年に249件のユーザビリティ問題の因子分析を踏まえて改訂された。さらに、2020年のページ更新では説明・例・リンクを加え、文言を少し整えた一方、著者は「10項目自体は1994年以来変わっていない」と述べる。この歴史説明は現行ページに記された著者の説明として引用し、現行の各文が1994年の原文そのものだとは主張しない。

ヒューリスティック評価は、評価者がインターフェースを一般原則に照らして点検し、問題を原則と結び付けて報告する検査方法である。Nielsen の説明では、評価者は画面を複数回見て原則への適合を調べる。実利用者が実タスクを行う実験とは異なり、実装前の紙面でも評価できる。方法は問題を見つける助けになるが、修正案を体系的に生成したり、修正版の品質を判定したりはしない。ゆえに、ヒューリスティックは設計レビューの根拠にはなるが、タスク成績を実測した実験結果とは区別する。

### 第8項と他の9項目の関係

現行記事の各番号の節を参照する。左の要旨は経験則の要約で、右は今回のデザインスキルへの応用である。第8項だけで削減を決めず、情報や操作を残す理由も点検する。

| 番号 | 経験則の要旨 | 簡素化の際の点検 |
| --- | --- | --- |
| 1 | システムの状態を適切な時期に知らせる | 保存中、完了、失敗などを見分ける表示が残っているか |
| 2 | 利用者の言葉と現実の慣例に合わせる | 専門用語、単位、並び順が読み手に通じるか |
| 3 | 誤った操作から離れたり戻したりできる | 取消や戻る操作が見つかるか |
| 4 | 一貫した表現と業界・プラットフォームの慣例を使う | 同じ状態を別の色や語で表していないか |
| 5 | エラーを起こしやすい条件を減らす | 必要な入力制約や誤操作を防ぐ手がかりを消していないか |
| 6 | 記憶の再生より、見て認識できる形を使う | ラベルを隠し、機能や前画面の値を覚えさせていないか |
| 7 | 初心者と熟練者の両方に効率的な使い方を用意する | よく使う操作や絞り込みの到達が悪化していないか |
| 8 | 課題に無関係な情報との競合を減らす | 見た目の量だけで削減を判断していないか |
| 9 | 問題と回復方法が分かるエラー表示を使う | エラーの文言と気づくための強調が残っているか |
| 10 | 必要な助けを課題に即して見つけられる形にする | 具体的な手順や必要な説明が探せるか |

## 2. 2007年論文が測ったもの

論文はクラッターを、過剰な項目、または項目の表現・配置が、あるタスクの遂行を損なう状態として定義する（導入「What is clutter?」、誌面 p.3）。この定義では、項目数と成績の関係をタスクごとに評価する。論文の評価対象は主に地図上の視覚探索で、指標は画素・局所特徴の統計から計算される。指標自体は、項目が業務上必要か、ラベルが意味的に理解されたか、操作後に判断が正しかったかを判定しない。

| 指標 | 論文の計算概要 | 読み取れる範囲と注意 |
|---|---|---|
| Feature Congestion (FC) | 誌面 pp.4–6、Figs. 4–5。CIELab 色、コントラスト・エネルギー／テクスチャ、向きの局所変動を複数スケールで評価する。局所共分散の楕円・体積に基づく特徴量を尺度間でまとめ、特徴量を正規化・合算し、画像全体で平均する。 | 目立つ特徴を加えるときの局所的な混み合いを表す初期的な指標。論文自身が単純な初期モデルと位置付け、特徴間の相互作用や最終的な組合せ方には追加研究が必要としている（p.5）。美的評価ではない。 |
| Subband Entropy (SE) | 誌面 pp.6–7。CIELab の L/a/b 各チャンネルを方向・空間周波数別の steerable-pyramid サブバンドに分解し、係数ヒストグラムの Shannon エントロピーを計算する。論文の合成は L に0.84、a・bに各0.08の重みを用いる。 | 画像符号化の冗長性・情報量の考え方を使う統計量。画面内の意味、情報の必要性、タスク達成を直接表す値ではない。重み付けを変えても論文中の地図例で結果はほぼ同じだったが、一般的なUIでの校正を意味しない。 |
| Edge Density (ED) | 誌面 p.8。MATLAB の Canny エッジ検出器を用い、画像中のエッジ画素の割合を数える。閾値は手動で低 .11／高 .27、σ=1.0。 | エッジの多さの代理量。論文は、項目サイズの影響を受けるため、異なる種類の探索課題をまたぐ比較には注意が要ると述べる（p.12）。 |

### 実験1: 地図での視覚探索

誌面 pp.8–10、Figs. 6–7。正常視または矯正視の6名が、ウェブから得た19枚の地図を背景に、Gabor パッチの有無を探索した。地図は同じ寸法に切り出され、平均輝度・色を灰色基準にそろえた。画面は約24°の視野を占め、ターゲット候補は注視点から約7.6°の6位置に置かれた。ターゲットの種類、位置、地図、ターゲット有無を組み合わせた条件で、正答試行の対数反応時間を画像ごとに平均し、各指標との関係を比較した。

19地図を単位とした相関は、ターゲット有／無の順に、FC r=.74/.76、SE r=.75/.77、ED r=.83/.83で、いずれも p<.001。論文は相関係数間に有意差を認めていない（p>.05）。これはこの地図セットで「指標値の高い画像ほど平均探索反応が遅い」という関連を示す。反応時間の改善を指標低下が引き起こしたという因果は示さない。

### 実験2: 地図上のコントラスト閾値

誌面 pp.11–12、Figs. 8–9。実験1と一部重なる20枚の地図で、左右を指す矢印を1秒間提示し、75%正答となるコントラスト閾値を測定した。候補位置は6か所で、正常視または矯正視の経験者4名が参加し、そのうち2名は著者だった。画像ごとの平均閾値との相関は FC r=.93、SE r=.68、ED r=.83（全て p<.001）。FC は SE より有意に高い相関を示した（p<.05）。ED は FC とも SE とも有意差がなかった。実験1とは成績指標も地図セットも異なるため、値の大小から画面一般でFCが常に最良だとは結論できない。

同じ節の標準探索課題では、指標値は名目上の項目数4、8、12、18とともに増えた。ただしEDは項目サイズに敏感で、異なる探索課題間の値をそのまま比べられないと著者は注意する（p.12）。これは単一の普遍的なクラッター尺度・閾値を想定しない根拠になる。

### 実験3: 色変動の操作

誌面 pp.15–17、Fig. 13（地図例はp.16、結果はp.17）。6枚の地図を元画像・グレースケール・赤系の3条件にし、計18画像で探索した。色変動を減らしながらエッジ密度と輝度チャンネルのサブバンド・エントロピーをおおむねそろえる操作で、4名が同様の探索課題を行った。

元画像のFC平均は6.3、赤系は5.8（p<.05）、グレースケールは5.1（p<.01）。エッジ画素率は元画像12.6%、赤系13.0%、グレースケール12.5%で有意差なし（p>.05）。探索時間では、ターゲット不在時は元画像1179 ms、赤系947 ms（対応t(23)=6.1, p<.001）、存在時は元画像772 ms、赤系552 ms（t(23)=11.8, p<.001）。存在時は元画像772 ms、グレースケール619 msにも差があった（t(23)=8.3, p<.001）。不在時の元画像1179 msとグレースケール1172 msは差がなく（p=.83）、著者は灰色のターゲットが灰色背景に溶け込んだ可能性を説明する。結果のパターンはFCが予測する方向と一致し、EDやSEは同じようには予測しなかった。

ここは単なる相関ではない。地図の色変動を操作した結果、対象となる探索条件では色の違いが成績を変えたという実験的証拠である。ただし標本は4名、対象は地図・Gaborターゲット・特定の位置と色処理であり、一般のアプリ画面で色を減らすと成果が上がること、FC低下自体が原因であること、色の意味的な符号をなくしてよいことは示さない。ターゲットと背景の色関係が成績に影響した点も重要である。

論文のまとめと Table 1（p.18）は、3指標が地図探索反応時間やコントラスト閾値と関連する一方、課題によって予測の違いがあることを示す。とりわけ実験3では、指標が同じ結果を返すわけではない。著者の結論は視覚探索指標としての評価であり、普遍的なUX品質スコアの認定ではない。

## 3. 画面設計での使い方

以下の設計判断は、タスク依存の定義と実験範囲に基づく推論である。

1. **必要情報を「多い」という理由だけで削らない。** 運用ダッシュボードの密な状態一覧は、異常原因の切り分けや複数指標の比較に必要なら、表示自体がタスクを支援することがある。タスク別にグループ化し、優先度を明確にし、頻度の低い情報は必要時に到達できる形にする。見た目の密度より、対象タスクの正確さ・時間・見落としを確認する。
2. **装飾は役割で判断する。** 色面、図形、イラスト、質感などが状態認識、カテゴリーの識別、階層、場所の記憶、ブランド理解を助けるなら、利用者の目標に結び付いた視覚要素になり得る。主情報と競合して読解を妨げる装飾は整理する。第8項は装飾禁止でもフラット化の命令でもない。
3. **数値指標は同条件の候補比較に限定して使う。** FC/SE/EDを使う場合は、同一タスク・同程度の表示条件・近いコンテンツの画面候補を比べる補助診断とし、値だけで採用を決めない。必要なラベルや意味のある色分けを維持した上で、実利用者のタスクテストで確認する。論文はUI向けの合格閾値を提示していない。

資料が根拠を与えるのは、具体的な利用者・タスク・成績に沿う判断である。グラデーションや中央揃えの禁止、全画面共通のクラッター合格点、必要情報の一律削除を定める規則は、いずれの資料にも示されない。
