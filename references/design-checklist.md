# デザイン確認チェックリスト

<!-- #region checklist -->

成果物の目的、読み手、媒体に合わせて必要な項目を確認するためのチェックリストです。項目は合否点ではありません。目的に関わる未解決の問題は、状態と影響を記録して報告します。

Markdownのチェックボックスは、コピーまたは印刷して記入するためのものです。記入内容を保存、集計するWebアプリではありません。

## 使い方

各項目のIDは固定です。記録や会話ではIDを使い、項目を足すときも既存のIDを振り直さないでください。媒体に関係しない項目は、理由を記録して対象外にできます。

| 表記 | 状態 |
| --- | --- |
| [ ] | 未確認 |
| [x] | 確認済 |
| [ ] 要修正: 内容 | 要修正。問題の記録を添えます |
| [ ] 対象外: 理由 | 対象外。理由を残します |

修正した項目は成果物を再確認してから確認済にします。確認していない内容を確認済にしないでください。
[x] は、問題がないこと、または修正後に期待する結果を確かめた状態を指します。単に見ただけの状態や、問題が残っている状態とは区別します。

## 1. 作成前

- [ ] PRE-01. 誰が、どの状況で、何を見つけ、判断し、実行するかを記録する。（実務確認）
- [ ] PRE-02. 最初に伝える結論を短い一文にし、成果物から読み取ってほしいことを定める。（実務確認）
- [ ] PRE-03. 必要な情報、条件、ラベル、単位、出典、状態を洗い出し、残す必要性を確認する。（実務確認）
- [ ] PRE-04. 対象の媒体、画面や紙面の条件、利用時の制約、既存の慣例を確認する。（実務確認）

## 2. 情報のまとまりと優先順位

- [ ] STR-01. 内容上の関係と、配置や共通の見た目が伝える関係が合っているか確認する。誤った結びつきも成果物で確かめる。（W1923を参考にした応用仮説）
- [ ] STR-02. 先に見つけてほしい情報と、比較のため同じ強さで示す情報を決める。主役の強調で必要な本文や条件を小さくしすぎていないか確認する。（実務確認）
- [ ] STR-03. 見出し、ラベル、順序から、数値の対象と集計範囲、合計と内訳、確認済みと未完了の違いを追えるか確認する。（実務確認）
- [ ] STR-04. 色、明暗、サイズ、太さ、向きなどの違いが競合し、目的の情報を探しにくくしていないか確認する。（R2007を参考にした応用仮説。混雑指標の算出ではありません）
- [ ] STR-05. 装飾や独自の表現が、文脈に合う意味を持ち、情報の識別や読み取りを妨げていないか確認する。（実務確認）

## 3. 必要な内容と表示状態

- [ ] CNT-01. 見た目を簡素にするとき、課題に必要な説明、条件、ラベル、状態、操作結果を失っていないか確認する。（N1994の経験則）
- [ ] CNT-02. 数値や図表に、読み取りに必要な単位、期間、更新時点、比較条件、凡例、出典があるか確認する。（実務確認）
- [ ] CNT-03. 色だけで状態や意味を区別させず、文言や形などでも識別できるか確認する。規格適合の判断には、対象規格を別途参照する。（実務確認）
- [ ] CNT-04. 想定する利用時の大きさで、必要な本文、条件、未完了事項を読めるか確認する。長い文字列、拡大、折り返しでの切れや重なりも確かめる。（実務確認）

## 4. 実物での確認

- [ ] VER-01. 対象媒体で成果物を表示し、実際に使う画面幅、ページ、表示倍率などの条件を記録する。（実務確認）
- [ ] VER-02. 修正前後を比べる場合は、内容、表示条件、データ、操作状態をそろえる。変えた条件があれば記録する。（実務確認）
- [ ] VER-03. 結論、比較の範囲、判断に必要な状態を成果物から読み取るなど、今回の課題を実物で試す。探し直しや誤認があれば記録する。（実務確認）
- [ ] VER-04. 操作を含む場合は、対象の操作と状態を実行して確認する。画像だけの確認では、操作やキーボード操作を確認したことになりません。（実務確認）
- [ ] VER-05. 読めない、探せない、対応が曖昧な箇所があれば、文字を縮めて詰め込まず構成を直し、同じ表示条件で再確認する。未確認の条件は未確認として残す。（実務確認）

## 5. 課題を記録して報告する

- [ ] REP-01. 問題の根拠・情報源（依頼文、ソース、画像、実画面など）と確認条件を記録する。実画面で見た事実と説明文から読み取った内容を分け、未確認ならその旨を記す。（実務確認）
- [ ] REP-02. 修正案と根拠の種類を対応づける。応用仮説は、対象の問題と確かめ方を添える。（実務確認）
- [ ] REP-03. 実際に行った確認、その条件と結果、未解決の問題を報告する。未解決の問題を修正済みと報告せず、レビューの提出と成果物の修正完了を分けて記録する。（実務確認）

## 媒体別の追加確認

必要な媒体の項目だけ使います。これらは基本チェックへの追加です。

### Web

- [ ] WEB-01. 対象となる画面幅で主要な移動や入力を実行し、表示と操作を確認する。（実務確認）
- [ ] WEB-02. Webサイトの第一印象を評価するときは、提示条件と評価対象を記録する。T2012はWebサイト画像の複雑さ、典型性、美的第一印象を扱った研究です。実操作の成功を示すものではありません。（T2012を参考にした応用仮説）

### スライド

- [ ] SLD-01. 実際の提示方法で表示し、読み手が見る距離や画面で文字、図、ラベルを確認する。（実務確認）
- [ ] SLD-02. 主張と根拠、図とラベル、出典の対応を追えるか確認する。（実務確認）

### 文書

- [ ] DOC-01. 見出しの階層と本文の順序が合い、目的の箇所へ移動できるか確認する。（実務確認）
- [ ] DOC-02. 注、脚注、図表の説明が、参照する本文や図表に正しく対応しているか確認する。（実務確認）

### 図表

- [ ] CHART-01. 軸、単位、期間、比較条件、凡例、出典が表示され、値の意味を追えるか確認する。（実務確認）
- [ ] CHART-02. 目盛りや基準線、強調によって差や傾向を誤って読ませていないか確認する。（実務確認）

## 課題の記録

項目ごとに必要な範囲で複製して使います。観察したこと、修正案、根拠、検証結果を分けて記録します。

| 記録する内容 | 記入欄 |
| --- | --- |
| 項目ID | __________________ |
| 観察した問題と確認条件 | __________________ |
| 問題の根拠・情報源（依頼文、ソース、画像、実画面など） | __________________ |
| 根拠・情報源の確認状態 | 確認済、未確認のいずれかを記入 |
| 修正案 | __________________ |
| 根拠の種類とID（研究結果、経験則、応用仮説、根拠を特定しない実務判断） | __________________ |
| 確認方法と条件 | __________________ |
| 確認結果 | __________________ |
| 未解決事項 | __________________ |

## 根拠の種類と限界

- W1923は、知覚上のまとまりに関する古典的研究です。点列、図形、線、運動などを扱います。現代UIの最適な余白や、特定の画面での改善効果を定めるものではありません。
- N1994は、ユーザビリティを点検する経験則です。特定の装飾や説明を減らせば、個別の成果物が必ず改善するという実験結果ではありません。
- R2007は、画像の視覚的な混雑指標と視覚探索などの関係を調べた研究です。このチェックリストの定性的な確認は、その指標を計算した結果ではありません。
- T2012は、Webサイト画像の視覚的複雑さや典型性と、美的な第一印象を扱った研究です。操作、理解、信頼、購買、長期満足への効果を示すものではありません。
- チェック項目の媒体別の使い方や確認方法は、研究結果そのものではありません。研究や経験則を個別の配置へ当てはめる場合は、応用仮説として扱い、修正案と実物での確認を結びつけます。
- 各項目末尾の「実務確認」は確認方法のラベルであり、根拠の種類ではありません。根拠の種類は研究結果、経験則、応用仮説に分けます。根拠を特定しない実務判断は、そのように記録します。今回の観察や試行の結果は「確認結果」に記録します。
- このチェックリストは、妥当性を検証した尺度や規格適合判定ではありません。項目を合計して品質の点数や合否を決めないでください。
