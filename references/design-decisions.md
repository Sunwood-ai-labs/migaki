# 設計と検証の手順

本資料は4原典を実務へ転用するための応用手順である。数値や特定の作風を原典が保証した手順ではない。根拠の範囲は [対応表](evidence-map.md)と各原典調査で確かめる。

## 1. 読み手の課題から調べる

最初に「誰が、どこで、何を見つけ、何を判断するか」を短く書く。新規作成なら依頼から仮置きし、既存成果物なら表示と内容を見て補う。

| 媒体 | 課題の例 | 先に確認すること |
| --- | --- | --- |
| 申込フォーム | 条件を理解して必要項目を入力する | 項目とラベル、必須・任意、補足、エラー、送信後の状態 |
| 業務ダッシュボード | 異常な対象と対応の優先順位を判断する | 正常との区別、単位、期間、更新時刻、絞り込み、詳細への移動 |
| スライド | 主張と、その根拠の関係を読み取る | 聴衆、視認距離、説明時間、図とラベル、出典 |
| 文書 | 条件と手順を読み違えずに実行する | 読む順序、見出し、例外、脚注と対象、段落間の関係 |
| 図表 | 特定の値・傾向・差を読み取る | 比較軸、系列と凡例、値と単位、強調の意味、不確実性 |

これは適用場面の例であり、4原典がすべての媒体を直接実験したという意味ではない。

## 2. 内容の構造を記録する

複雑な画面では要素の役割を表にする。小さな修正なら内部メモで足りる。

| 要素 | 読み手の課題との関係 | 所属するまとまり | 表示上の役割 | 残す条件 |
| --- | --- | --- | --- | --- |
| 未処理件数 | 対応量を判断する | 対応状況 | 主要情報 | 期間と対象を併記する |
| 最終更新時刻 | 情報の鮮度を判断する | データの状態 | 補助情報 | 小さくしても読めるようにする |
| 異常の警告 | 優先して対応する | 該当する対象 | 重大な状態 | 色に加えて文言を残す |
| 背景の模様 | ブランドの印象を作る | 背景 | 装飾 | 値や警告の識別を妨げない |

主要情報は常に一つとは限らない。比較が目的なら比較対象が同じ強さで並ぶ必要がある。警告が発生すれば、その状態に応じて優先順位が変わる。

## 3. まとまりを修正する

W1923の議論を参考に、内容の所属と、知覚上の結びつきが食い違う場所を探す。

| 観察した問題 | 応用仮説としての修正 | 実物で確認すること |
| --- | --- | --- |
| ラベルが対応する値より隣の値に近い | ラベルと値を同じ単位として配置する | 読み手がどのラベルをどの値に対応づけるか |
| 同じ段落の行間より、別の段落との間隔が狭い | 意味の境界と間隔の違いを一致させる | 改行や折り返し後も境界を誤認しないか |
| 無関係なカードが同じ強い色で結ばれて見える | 共通の意味を持つ要素だけに共通の表現を与える | 色を使わない状態でも関係を読めるか |
| 表の見出しと値が別の列に見える | 揃える位置、列の幅、間隔を見直す | 長い見出しでも所属がずれないか |
| 図の線が交差して系列を追えない | 線の経路やラベルの位置を変える | 始点から終点まで追跡できるか |

まとまりの説明に、余白だけを使う必要はない。必要なら見出し、枠、背景、区切り線を使う。ただし「共通領域」の現代的な用語や実験を、1923年の原典にさかのぼって帰属させない。

### 競合を調べる例

次の配置で、内容上の正しい組み合わせが「氏名と山田」「部署と営業」なら、配置と見た目をそれに合わせる。

```text
誤認の懸念がある配置
氏名                 山田   部署                 営業

修正候補
氏名  山田                 部署  営業
```

これは概念上の例である。比例フォントの実画面での間隔を表してはいない。修正後の画面で実際のまとまりを確認する。

## 4. 強調の役割を整理する

R2007を、要素数だけでなく視覚的特徴の競合にも注目する手がかりとして使う。

1. 主要な情報と、それを探す際に競合する要素を特定する。
2. 色、明暗、サイズ、太さ、向き、囲み、動きのうち、競合に関係する違いを調べる。
3. 意味を担わない違いを減らすか、役割のある違いに置き換える。
4. 目的の情報と、関連する補助情報の両方を見つけられるか確認する。

「全部を強調しない」は状況に応じた助言である。「強調を一つにすれば必ず改善する」という研究結果にしない。たとえば異常項目が複数あるなら、同じ種類の異常を同じ強さで示す方が課題に合う場合がある。

| 表現 | 役割がある使用例 | 見直す使用例 |
| --- | --- | --- |
| 色 | 同じ状態や系列を一貫して示す | 意味のない色分けが状態色と競合する |
| 大きな文字 | 読み手が先に知りたい値や主張を示す | すべての値が大きく、比較の基準がない |
| 太字 | 結論、重要な条件、見出しを区別する | 文中の多数の語を同じ強さで強調する |
| 影や囲み | 前後関係や操作対象を示す | 同じ意味のない層や小枠が増えている |
| 背景の装飾 | ブランドや場面の意味を伝える | 値やラベルの識別を妨げる |

R2007のfeature congestionを計算していない場合は、スコアやヒートマップを「算出した」と報告しない。画像を見た感想は定性的な観察として残す。

## 5. 削減前に必要性を確かめる

N1994の第8原則で問うのは、読み手の課題に対して情報が必要かどうかである。他の原則と併せて点検する。

| 減らす候補 | 残す必要があるかを調べる問い |
| --- | --- |
| 繰り返す説明 | 対象や条件が変わるので再掲が必要ではないか |
| 入力の補足 | 制約や例がないと誤入力が増えないか |
| 状態の表示 | 更新中、保存済み、失敗を判断できなくならないか |
| ラベル | アイコンや位置だけで機能を思い出す必要が生じないか |
| 凡例・単位・出典 | 値の意味、比較条件、出所が曖昧にならないか |

削除より、文の短縮、関連箇所への移動、見出しの改善、詳細の段階的な表示が適する場合がある。段階的な表示もその情報を必要とする頻度と到達のしやすさを確かめる。

## 6. 作風を目的に合わせる

T2012はWebサイト画像の第一印象に関する知見である。その種類のサイトとして想定される見た目から外れる場合、何が意図的で、何が理解を妨げるのかを分ける。

| 相談 | 判断の仕方 |
| --- | --- |
| グラデーションを使いたい | 面の区別、ブランド、強調などの役割を確認し、文字との関係を実物で見る |
| 中央揃えにしたい | 短い題名や招待状などの目的と、連続して読む文章の追いやすさを分けて検討する |
| 全部カードにしたい | 各要素が独立した単位か、比較や連続した読み順が必要かを確かめる |
| 管理画面を余白の多い画面にしたい | 同時に比べる情報が減り、画面移動が増えないかを確かめる |
| 独創的なレイアウトにしたい | 見慣れた操作や内容の関係を保ちながら、どこで独自性を出すかを選ぶ |

「典型性」を古いデザインのコピー、特定のジャンルへの従属、すべてを同じ見た目にする命令に変換しない。今回の読み手にとっての慣れは原典の参加者の評定と同じとは限らない。

## 7. 課題ごとに検証する

### 比較する条件

修正前後で内容・画面幅・拡大率・データ・操作状態を揃える。条件を変えた場合は差を明記する。新規作成で比較対象がなければ、完成物と依頼の課題を照合する。

### 確認の種類

| 確認 | 見るもの | 言える範囲 |
| --- | --- | --- |
| 内容照合 | 必要な項目、値、単位、条件、出典 | 内容の保持。読み手の理解までは保証しない |
| レンダリング確認 | 指定媒体の表示、折り返し、重なり、切れ | その条件で見えた状態 |
| 操作確認 | 対象の操作、エラー、ローディング、完了 | 実行した操作と状態の動作 |
| 課題の試行 | 目標情報の特定、値の照合、関連の説明 | 実行者がその条件で達成した結果 |
| 対象利用者による評価 | 探索、理解、判断、操作、好みなど | 参加者・課題・条件の範囲での結果 |

5秒表示、ぼかし、縮小、モノクロなどを使う場合は、実務上の簡易確認と説明する。5秒という時間はT2012の提示条件から導いた必須値ではない。短時間提示による美的評定を、読み取りや操作の成功と同じ評価にはしない。

探索時間や誤答を測る場合は、測定方法、課題、試行数、順序、参加者を記録する。慣れや順序の影響がある少数の試行から、一般的な改善率を発表しない。

### 未確認として残す例

- コードだけを読んだ場合、実画面の表示は未確認。
- 画像だけを見た場合、フォーカス移動、読み上げ、操作は未確認。
- 自分で操作した場合、対象利用者の理解や好みは未確認。
- 第一印象だけを評価した場合、長期の作業効率と成約率は未確認。

## 報告の例

```text
修正案
支払額の近くに通貨単位と対象期間を配置する。

観察した問題
金額は大きく表示されているが、通貨単位と対象期間が別の枠に離れている。

根拠と判断
W1923の近接の議論を参考にした応用仮説。関連する値と条件を一緒に読める配置にする。

確認結果
表示確認では金額と条件の対応を追える。対象利用者の誤読が減るかは未確認。
```

項目をすべての小修正で機械的に繰り返す必要はない。複数の変更をまとめて、利用者の課題、根拠、確認範囲が伝わる形にする。
