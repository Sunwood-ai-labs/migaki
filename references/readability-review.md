# 読み取りを確かめて組み直す

この手順は実務上の確認方法です。4原典が定めた合格基準や、利用者による評価の代わりではありません。

## 配置する前に、何を伝えるかを決める

読み手が最初に持ち帰る結論を短い一文にする。次に、判断に必要な条件、比較、未完了事項を選ぶ。原文を順に並べるだけで構成を決めない。

数値には対象、期間、集計範囲、単位を対応づける。全体の変化と最終回の内訳など、範囲が違う数値を同列の見出しとして置く前に、包含関係を明示する。棒の長さを比較させるなら、共通の尺度も対応づける。

確認済み、未確認、保持、未実施、承認待ち、今後の案を混同しない。判断に影響する状態は、色と小さな脚注に任せず、対応する内容の近くに言葉で示す。

## 使う大きさで読んでから直す

画像のピクセル数や編集画面の拡大表示だけで、読みやすさを判断しない。共有先での表示幅、紙面、投影条件など、今回分かる利用条件を記録する。利用条件を確認できない場合は、仮定した条件と未確認の範囲を示す。

1. 結論、必要な本文、判断に必要な条件や未完了事項を、想定する表示で拡大せずに読む。
2. 見出しの順に読み、数値の対象と比較範囲、確認済みと未完了の違いを説明できるか試す。
3. 読めない箇所、探し直した箇所、対応が曖昧な箇所を特定する。確認しただけで確認済みにしない。
4. その箇所の構成を直し、同じ表示条件で再確認する。

大きな数値のために本文や重要な条件を縮めていないかを見る。収まらない場合は、主役の大きさ、見出し、配置、重複説明を見直す。ページ数や形式を変更できる依頼なら、詳細を別ページへ分ける案も検討する。単一ページが指定されている場合は、その制約の中で組み直し、承認待ちや未確認事項など判断に必要な内容を消さない。存在しない詳細ページやリンクを作らない。

自分で読んだ結果を、対象利用者の理解や作業時間の改善として報告しない。元の資料が述べる作業結果と、今回の表示確認で分かったことも分ける。

## 架空の報告資料に当てはめる

次は説明用の架空例であり、ユーザーの実データや、表示確認済みの完成品ではない。

素材には「開始時の空き1.20 GiB」「整理後13.20 GiB」「3回合計で12.00 GiB増加」「最終回の削除8.50 GiB」がある。また「未確認の6件は削除せず保持」「指定版の復元と起動を確認済み」「一覧の共有は承認待ち」という状態がある。

読み手の課題を「全体の成果と、まだ終わっていないことを把握する」と置く場合、次の順で組み立てられる。

| 読む順番 | 伝える内容 |
| --- | --- |
| 結論 | 空き容量が3回の整理で12.00 GiB増加し、現在13.20 GiBになった。 |
| 比較 | 開始時1.20 GiBから整理後13.20 GiBへの変化。 |
| 範囲を限定した詳細 | 最終回の削除量は8.50 GiB。全3回の増加量とは区別する。 |
| 状態 | 未確認の6件は保持。指定版は復元・起動確認済み。一覧の共有は承認待ち。 |

この文章の順序だけで完成とはしない。実際に組んだ成果物から「全体でいくら増えたか」「最終回の値は何か」「何が承認待ちか」を読み取れるか確かめる。必要な本文や状態が小さすぎる場合は、配置や情報の分け方を直す。
